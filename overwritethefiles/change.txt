new changes
=============

models:
========
users.py
- Added the is_admin column with a migration that preserves existing accounts.
- Added admin_access_requests to save each account's reason, status, request date,
  reviewer, and decision date in SQLite.
- Added helpers to find users by ID and list admin or non-admin accounts.
- Added creation of new admin accounts and promotion of existing accounts.
- Added email and password validation. Existing-account promotion preserves the
  account's password and other data; new passwords are stored as hashes.
- Added removal of admin access without deleting the account or its documents.
- Prevented removal of the last admin or the acting admin's own access.
- Added request submission, listing, approval, and rejection helpers. Duplicate
  requests and repeated decisions do not overwrite the saved result.
- Approval grants the admin role and saves the reviewer and UTC timestamp in
  the same transaction. Self-approval and non-admin decisions are blocked.
- Direct promotion also resolves an existing access request.
- Used transactions and database role checks to protect concurrent role changes.
- Updated login verification to return the account's admin role.
- Closed SQLite connections after commit or rollback to avoid open file handles.
- Added comments explaining migrations, permissions, and database operations.

users.db (project root; local account setup)
- Created admin@gmail.com as the initial admin account with a hashed password.
- Created demo.alice@example.com, demo.ben@example.com, and
  demo.chloe@example.com with pending admin-access requests for testing.
- These were one-time database changes, not accounts recreated on app startup.
- Later approvals or removals may have changed their current roles and statuses.

routes:
=======
admin.py
- Added the Admin Management page at /admin/management and
  /admin/admin_management.html.
- Made both /admin and /admin/ redirect to Admin Management.
- Allowed any signed-in account to view those management pages without an admin
  role. This does not grant that account admin permissions.
- Kept admin-role checks for account-changing actions and other protected admin
  pages. Non-admin access to those routes redirects to /admin-access.
- Kept login checks and cleared sessions that reference a missing account.
- Added POST routes to create/promote admins, remove admin access, and approve
  or reject access requests, with CSRF validation and input/error handling.
- Passed the current admins, available accounts, and pending requests to the page.
- Excluded existing admins from the pending approval queue.
- Added success messages and redirects after saving to avoid repeat submissions.
- Restored the approval routes after the temporary commenting-out change.

auth.py
- Redirected admin logins to /admin/dashboard and client logins to /client/upload,
  including AJAX login responses.
- Added /admin-access for signed-in users to submit an access request or view
  its saved status. Existing admins are redirected to the admin dashboard.
- Checked the form token and required a reason of 10 to 1,000 characters.
- Associated requests with the signed-in user instead of accepting a user ID
  from the submitted form.

app:
======
__init__.py
- Initialized the user database and admin-role migration during app creation.
- Added the grant-admin console command to promote an existing account by email.
- Made console promotion update any existing access request to approved.
- Added a Codex handoff comment asking which accounts should be admins before

- Added a random CSRF token stored in the user's session.
- Added token validation for request, approval, and admin-management forms.
- Used constant-time token comparison and rejected missing or invalid tokens.
- Added comments explaining the form protection.

config.py
- Replaced the fixed session secret with the SECRET_KEY environment variable.
- Added a random fallback key when no environment value is configured.
- Documented that the fallback signs users out when the server process restarts.
